# DEC-005: ccorch is pane orchestration only

- **Status**: Accepted (2026-10-04)
- **Partially supersedes**: DEC-004 (the agent catalog, the spawn gate, the ledger and `/ccor-parallel`). DEC-004's three pane conditions stand.
- **Reinstates**: DEC-001 and DEC-003 (see "Status of DEC-001 and DEC-003")

## Decision

ccorch is pane orchestration only; in-session distribution moved to ccharness.

ccorch keeps what splits work into **separate sessions**: the `/ccor` tmux
panes, used under the three conditions DEC-004 fixed:

1. Work that writes to another repository
2. Work that must run under the target repository's permission/hook layer
3. Work that needs real-time visual supervision

## Reasons

The plugins were re-split by axis. ccorch's axis is work split into
**separate sessions** (panes). How work is distributed **inside one session**
— the leaf agent catalog, the parallel worktree fan-out (`parallel-worktree`
skill, cleanup only through worktree-sweep, never `--force` or `branch -D`), the
catalog tier guard and the agent ledger — is provided by ccharness 0.9.0, if
installed. Until this release both plugins shipped overlapping parts of that
set. One plugin per axis removes the overlap and the drift between two copies.

## What moved

| ccorch 0.4.0 | If ccharness is installed |
|--------------|-----|
| 8 leaf agent types `ccorch:<type>` | `ccharness:<type>` |
| `/ccor-parallel` | `/ccharness:parallel-worktree` |
| catalog tier guard hook | ccharness's catalog tier guard |
| agent ledger (`.claude/ccorch/ledger.jsonl`) | `<main checkout>/.claude/ccharness/ledger.jsonl` |

Removed from ccorch: `agents/`, `skills/ccor-parallel/`, the three hooks for
the guard and the ledger, and the ledger format document. `hooks/hooks.json`
keeps only the Stop entry for `stop_signal.sh`.

## What was retired

`url-extract` was retired, not moved. Basis: the WebFetch tool description in
Claude Code, as of 2026-10, says it answers through a small fast model, so a
dedicated extraction leaf adds a spawn without adding capability.

## Status of DEC-001 and DEC-003

DEC-004 marked DEC-001 (tmux wait-for signaling) and DEC-003 (`/tmp` work
directory) as superseded, because v2 made subagents the default. With panes the
only mode again, the code was read to see what it does now:

- `scripts/ccorch-wrapper.sh`: its `cleanup` trap runs
  `tmux wait-for -S "$PARENT_CHANNEL"`; results and status files are written
  under `CCORCH_WORK_DIR`.
- `hooks/stop_signal.sh`: signals the parent with `tmux wait-for -S`.
- `skills/ccor/SKILL.md`: creates `/tmp/ccorch/${SESSION_ID}` and waits with
  `tmux wait-for "$CHANNEL"` in the background.

So both decisions are in effect: DEC-001 and DEC-003 are **Approved** again,
and DEC-004's supersession of them is withdrawn. DEC-002 (depth propagation by
environment variables) is unchanged. No code changed for this.

## Consequences

- Rules, prompts and docs elsewhere that name `ccorch:*` agent types or
  `/ccor-parallel` must switch to the ccharness names before this release is
  merged.
- ccorch 0.5.0 no longer writes `.claude/ccorch/ledger.jsonl`.
- Safety: the descriptions now say what the wrapper does and what is unverified; see [NFR-SEC-003](../../requirements/nfr/security.md#nfr-sec-003-structural-depth-overflow-prevention). The wrapper is unchanged here.
- Later change (0.6.1): `hooks/stop_signal.sh` now signals only once the pane's result file exists, and copies the Main Brain's result to `result.md` first; the skill waits until `result.md` exists. See [wrapper-script.md](../components/wrapper-script.md#completion-signal-the-stop-hook-and-resultmd).
