# DEC-004: v2 — Subagent-Default Hybrid Orchestration

- **Status**: Accepted (2026-07-15, scope extended 2026-08-10)
- **Supersedes**: DEC-001 (tmux wait-for signaling), DEC-003 (/tmp work directory)
- **Inherits**: DEC-002 (depth control — reimplemented as tool exclusion, see below)

## Decision

ccorch v2 replaces the tmux-pane execution substrate with the Claude Code native
subagent substrate (background Agent + SendMessage resume, and worktree-isolated
agents for parallel writes). Pane launch remains available for exactly three
conditions:

1. Work that **writes to another repository** (subagents cannot write outside
   the session's repository; reads, network, and `gh api` are fine)
2. Work that must run under the **target repository's enforcement layer**
   (permission deny rules / hooks) as a safety net
3. Work that needs **real-time visual supervision**

Everything else runs on the subagent substrate by default.

## What the harness already provides (do not reimplement)

Measured 2026-08-09 (parallel write spike, 3 spikes over Agent isolation and
Workflow):

- Worktree creation, branch creation (`worktree-agent-<id>` / `worktree-wf_*`),
  locking (owned by the main session, released when the agent completes), and
  automatic cleanup of **unchanged** worktrees
- Completion notification, transcript-preserving resume (SendMessage), agent
  isolation
- Subagents **can** `git commit` inside their own isolated worktree of the same
  repository (the old "subagents cannot write" rule only holds across
  repositories)

## What ccorch v2 adds — the four orchestrator responsibilities

1. **Origin pinning** — with `worktree.baseRef: head`, the orchestrator's cwd
   HEAD determines the fan-out base for every spawned worktree. Pin and record
   HEAD before fan-out; do not move between launches.
2. **Collection of changed worktrees** — changed (committed) worktrees and
   branches survive agent completion and are the orchestrator's responsibility:
   preserve untracked artifacts, then `git worktree remove --force`, then delete
   the branch (only after merge — see ordering note in the skill).
3. **Integration merge** — merge worker branches in a dedicated integration
   worktree, `--no-ff` by default for symmetric history. Never touch main.
4. **Capture preservation** — session-capture files (e.g. ccmemo SECI
   `context-*.md`) generated inside worker worktrees are destroyed with the
   worktree; move them to the main checkout's `.claude/tasks/` before removal,
   suffixing the worker name to avoid same-second filename collisions.

## Bundled agent catalog (fixed model / effort)

Leaf agents ship with `model` and reasoning effort pinned in frontmatter, so
"forgot to specify a model" (which silently inherits the expensive main-session
model) becomes "picked a type with the right cost". Effort buys reasoning
depth, not context breadth: collection/extraction/transformation leaves get
low–medium; high is reserved for refutation/verification where depth is the
job itself. Escalation is deterministic: on insufficient quality the
orchestrator re-runs the same prompt one model tier up — the LLM does not
decide its own escalation.

Depth control (DEC-002's intent) is enforced structurally: no bundled agent has
the Agent tool, so leaves cannot spawn sub-leaves.

## Anti-catalog (deliberately not built)

1. KB-recall search agent (rejected 2026-07-16; deterministic search is cheaper)
2. Judgment/design agents — synthesis and decisions stay in the main session
3. Pure exploration agents — native `Explore` already exists (native-first)
4. Git external-integration agents (push / PR / GitHub / GitLab API) — external
   reach is a main-session responsibility via MCP + auth gates; local git
   mechanics are covered by worktree-worker plus deterministic orchestrator steps
5. Phase/process agents ("X-driven development") — process management belongs
   to skills and human approval gates; what a phase fixes is the output contract,
   not the model

## Billing constraint — subscription-only

All v2 execution elements (interactive sessions, subagents, Workflow,
cross-session messaging) must stay within subscription plan usage. Headless
`claude -p` workers are rejected (announced default change makes bare mode
require pay-per-use billing). Cross-session handoff is resume or
"summary + file pointers"; messaging is text-only.

## New v2 components

- **Ledger hooks** — PreToolUse gate (parallel cap + model routing guard) and
  PostToolUse / SubagentStop recorders maintaining a thread-name → agentId
  ledger (`.claude/ccorch/ledger.jsonl`). Agents do not know their own agentId,
  so the orchestrator side must record it; a forgotten entry means a lost
  resume handle.
- **`/ccor-parallel` skill** — the four responsibilities as an executable
  procedure.
- **Agent catalog** — `agents/*.md` (nine types).

## Rejected alternatives

- Repairing the v1 wrapper (~400 lines): discarded parts get no repair; v1 is
  frozen for the three pane conditions
- Reinventing `/batch`: overlap with the official skill is avoided; v2 keeps
  only its differential (four responsibilities, subscription-only, capture
  preservation, depth control, ledger, model-routed catalog)
- Agent-teams substrate: no worktree isolation, experimental, ~7x token cost
