# US-004: Multi-Layer Safety

## User Story

**As a** Claude Code user
**I want to** child panes to be safe while running in auto mode (`--permission-mode auto`)
**So that** the risk of unrestricted agents performing destructive operations is minimized

## Acceptance Criteria (EARS Notation)

### Functional Requirements

- **REQ-004-001**: When launching the Main Brain (DEPTH=1), the system shall start it with `--permission-mode auto` and the base `--disallowedTools` rules (`rm -rf`, force push, `git reset --hard`, `git clean`, `sudo`)
  - Verified (0.6.0): [NFR-SEC-001](../nfr/security.md#nfr-sec-001-tool-restriction-enforcement), `tests/test_wrapper.sh`.
- **REQ-004-002**: When launching a Child (DEPTH=2), the system shall specify `--disallowedTools` rules that are the DEPTH=1 rules plus `Bash(git push *)`
  - Verified (0.6.0): [NFR-SEC-001](../nfr/security.md#nfr-sec-001-tool-restriction-enforcement), `tests/test_wrapper.sh`.
- **REQ-004-003**: When launching a Grandchild (DEPTH=3), the system shall add `Agent` and `Bash(tmux *)` to the DEPTH=2 `--disallowedTools` rules to prohibit new pane creation
  - Verified (0.6.0): [NFR-SEC-003](../nfr/security.md#nfr-sec-003-structural-depth-overflow-prevention), `tests/test_wrapper.sh`. Deny rules hold in every permission mode.
- **REQ-004-004**: When launching a pane at any depth, the system shall inject guard rail rules for that depth via `--append-system-prompt`
- **REQ-004-005**: If the Bash tool is permitted, the system shall apply deny rules such as `Bash(rm -rf *)` and `Bash(git push --force *)`
  - Verified (0.6.0) as a rule layer, not a boundary: Bash deny rules catch the usual command form only. See [NFR-SEC-002](../nfr/security.md#nfr-sec-002-destructive-operation-prevention).

## Depth-Based Tool Permissions

| Tool | DEPTH=1 | DEPTH=2 | DEPTH=3 |
|------|---------|---------|---------|
| Read | Yes | Yes | Yes |
| Edit | Yes | Yes | Yes |
| Write | Yes | Yes | Yes |
| Bash | Yes (base deny rules) | Yes (adds `git push` deny) | Yes (adds `tmux` deny) |
| Grep | Yes | Yes | Yes |
| Glob | Yes | Yes | Yes |
| Agent | Yes | Yes | **No** |

## Guard Rail Prompt Examples

```
DEPTH=1: "You are a CCORCH Main Brain (DEPTH=1). You can delegate tasks to child panes.
Destructive git operations (push --force, reset --hard) are prohibited."

DEPTH=3: "You are a CCORCH Grandchild (DEPTH=3). You must not create new panes.
Execute only your assigned task."
```
